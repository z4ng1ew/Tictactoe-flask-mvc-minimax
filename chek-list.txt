### Главная часть

**Задание 1. Создание структуры проекта**
1) Каждый слой является отдельным модулем.
2) Структура проекта имеет следующие слои: web, domain, datasource, di.
3) Слой web включает в себя как минимум пакеты model, module, route, mapper.
4) Слой domain включает в себя как минимум пакеты model, service.
5) Слой datasource включает в себя как минимум пакеты model, repository, mapper.

**Задание 2. Реализация domain-слоя**
1) Описана модель игрового поля в виде целочисленной матрицы.
2) Описана модель текущей игры, у которой есть UUID и игровое поле.
3) Описан интерфейс сервиса, у которого есть следующие методы: метод получения следующего хода текущей игры алгоритмом Минимакс, метод валидации игрового поля текущей игры, метод проверки окончания игры.
4) Модели, интерфейсы, реализации находятся в разных файлах.

**Задание 3. Реализация datasource-слоя**
1) Реализован класс-хранилище для хранения текущих игр.
2) В качестве средства хранения использованы потокобезопасные коллекции.
3) Описаны модели игрового поля, текущей игры.
4) Реализованы мапперы domain<->datasource.
5) Реализован репозиторий для работы с классом-хранилищем, у которого есть следующие методы: метод сохранения текущей игры, метод получения текущей игры.
6) Создан класс, реализующий интерфейс сервиса и принимающий в качестве параметра репозиторий для работы с классом-хранилищем.
7) Модели, интерфейсы, реализации должны находиться в разных файлах.

**Задание 4. Реализация web-слоя**
1) Описаны модели игрового поля, текущей игры.
2) Реализованы мапперы domain<->web.
3) Реализован контроллер с использованием Flask, имеющий метод POST /game/{UUID текущей игры}, который отправляет текущую игру с обновлённым игровым полем пользователем и получает в ответ текущую игру с обновлённым игровым полем компьютером.
4) Если отправлена некорректная текущая игра с обновлённым полем, возвращается ошибка с описанием.
5) Есть поддержка нескольких игр одновременно.
6) Модели, интерфейсы, реализации находятся в разных файлах.

**Задание 5. Реализация di-слоя**
1) Реализован класс Container, в котором описывается граф зависимостей.
2) Класс-хранилище определён в качестве singleton.
3) Определён репозиторий для работы с классом-хранилищем.
4) Определён сервис для работы с репозиторием.

### Модуль — что это?

В Python **модуль** — это просто **папка с файлами кода** у которой внутри есть специальный файл `__init__.py` (он может быть пустым). Этот файл говорит Python: *"эта папка — не просто папка, это модуль, из неё можно импортировать код."*

```
domain/
├── __init__.py   ← вот этот файл делает папку модулем
├── model.py
└── service.py
```

Без `__init__.py` — просто папка. С ним — модуль.

---

### Слой — что это?

**Слой** — это группа файлов которая отвечает **за одну конкретную задачу.** Это не технический термин Python, это просто договорённость между программистами как организовать код.

---

### Простая аналогия — многоэтажный дом

Представь дом где каждый этаж делает своё дело:

| Этаж (слой) | Что делает | В проекте |
|---|---|---|
| **web** | Общается с жильцами снаружи | Принимает запросы от пользователя |
| **domain** | Мозг дома, принимает решения | Логика игры, Минимакс |
| **datasource** | Подвал, хранит вещи | Хранилище игр в памяти |
| **di** | Управляющий домом, всех связывает | Собирает всё вместе |

**Каждый этаж не лезет в дела других.** Подвал не решает кого пускать в дом — это дело первого этажа.

---

### В коде это выглядит так:

```
src/
├── web/              ← слой + модуль (есть __init__.py)
│   ├── __init__.py
│   ├── model.py
│   └── route.py
│
├── domain/           ← слой + модуль
│   ├── __init__.py
│   ├── model.py
│   └── service.py
│
├── datasource/       ← слой + модуль
│   ├── __init__.py
│   ├── model.py
│   └── repository.py
│
└── di/               ← слой + модуль
    ├── __init__.py
    └── container.py
```

---

### Зачем делить на слои?

Без слоёв весь код в одном файле — это как жить в однокомнатной квартире где кухня, туалет и спальня в одном месте. Работает — но очень неудобно и грязно.

Слои — это **разные комнаты** для разных задач. Каждая комната знает своё дело.

### model, repository, mapper в слое datasource

---

### model — описание данных для хранения

Похож на model из domain, но заточен **под хранение**, а не под логику.

```python
# datasource/model/game_ds_model.py
class GameDatasourceModel:
    uuid: str
    field_json: str  # поле хранится как строка, а не как объект
```

Зачем отдельный model если в domain уже есть?

Потому что **хранилище видит данные иначе** чем логика. Для хранения удобнее строки и числа. Для логики — объекты с методами.

### repository — работник архива

**Задача:** сохранить игру и достать игру. Больше ничего.

```python
# datasource/repository/game_repository.py
class GameRepository:
    
    def save(self, game):
        # положить игру в хранилище
        self.storage[game.uuid] = game
    
    def get(self, uuid):
        # достать игру из хранилища по UUID
        return self.storage[uuid]
```

Это **архивариус** — знает только где лежит папка и как её достать. Не читает содержимое, не думает над ним.

### mapper — переводчик между datasource и domain

Точно такой же переводчик как в web, но между другими слоями.

```python
# datasource/mapper/game_mapper.py

# объект domain → объект datasource (для сохранения)
def domain_to_datasource(domain_game):
    return GameDatasourceModel(
        uuid=domain_game.uuid,
        field_json=str(domain_game.board.cells)
    )

# объект datasource → объект domain (после получения)
def datasource_to_domain(ds_model):
    return Game(
        uuid=ds_model.uuid,
        board=Board(cells=eval(ds_model.field_json))
    )
```

### Единая аналогия — библиотека

| Пакет | Аналогия | Что делает |
|---|---|---|
| **model** | Карточка книги в каталоге | Описывает как книга хранится в системе |
| **repository** | Библиотекарь | Берёт и кладёт книги на полку |
| **mapper** | Переводчик | Переводит карточку каталога в настоящую книгу и обратно |

---

### Путь данных через datasource:

```
domain говорит: "сохрани эту игру"
        ↓
[mapper]      — перевёл Game → GameDatasourceModel
        ↓
[repository]  — положил GameDatasourceModel в хранилище
        ↓
        ...позже...
        ↓
domain говорит: "дай игру 550e8400"
        ↓
[repository]  — достал GameDatasourceModel из хранилища
        ↓
[mapper]      — перевёл GameDatasourceModel → Game
        ↓
domain получил объект Game с которым умеет работать
```

### Главный вопрос — зачем три отдельных пакета?

Завтра решил хранить не в памяти а в **настоящей базе данных:**
- меняешь только **repository** — как достаём и кладём
- меняешь только **model** — как выглядят данные в базе
- **mapper** почти не трогаешь
- **domain вообще не трогаешь** — он не знает где хранятся данные

Слои защищают друг друга от изменений.

Это пакеты внутри слоя **web**. Каждый — отдельная папка со своей задачей.

---

### model — описание данных

**Задача:** описать как выглядят данные которые приходят и уходят через веб.

```python
# web/model/game_model.py
class GameWebModel:
    uuid: str
    field: list  # игровое поле в виде JSON
```

Это просто **шаблон данных** — как бланк документа. Никакой логики, только структура.

---

### route — адреса запросов

**Задача:** сказать Flask какой код запускать когда приходит запрос на конкретный адрес.

```python
# web/route/game_route.py
@app.route('/game/<uuid>', methods=['POST'])
def make_move(uuid):
    ...
```

**Route** (маршрут) — это как **номер кабинета** в учреждении. Пришёл по адресу `/game/550e...` — попал в нужный кабинет.

---

### mapper — переводчик между слоями

**Задача:** конвертировать (переводить) данные из формата web в формат domain и обратно.

```python
# web/mapper/game_mapper.py

# JSON от пользователя → объект domain
def web_to_domain(web_model):
    return DomainGame(uuid=web_model.uuid, field=web_model.field)

# объект domain → JSON для пользователя  
def domain_to_web(domain_game):
    return GameWebModel(uuid=domain_game.uuid, field=domain_game.field)
```

Это как **переводчик** между двумя людьми которые говорят на разных языках. Web говорит на JSON, domain говорит на Python-объектах.

---

### module — точка сборки слоя

**Задача:** собрать всё внутри слоя web вместе — соединить route, mapper, model в одно целое.

```python
# web/module/game_module.py
from web.route import game_route
from web.mapper import game_mapper
from web.model import game_model
# всё подключено в одном месте
```

Это как **оглавление книги** — сам текст в других файлах, но здесь написано где что искать.

---

### Итого — путь одного запроса внутри web:

```
Запрос от пользователя (JSON)
        ↓
    [route]    — поймал запрос по адресу /game/{uuid}
        ↓
    [mapper]   — перевёл JSON → объект domain
        ↓
    [model]    — структура по которой mapper работает
        ↓
  уходит в слой domain...
  ...возвращается из domain...
        ↓
    [mapper]   — перевёл объект domain → JSON
        ↓
Ответ пользователю (JSON)
```

**module** при этом просто держит всё это вместе как папка с документами.

### Аналогия — Почта

---

Представь что слой **web** — это **почтовое отделение.**

---

**route — стойка приёма посылок**

Клиент приходит и говорит: *"хочу отправить посылку в город Минимакс"*

Стойка определяет: *"посылки в этот город принимаем здесь, по этому адресу"*

Именно route решает — какой запрос куда направить.

---

**model — стандартный бланк посылки**

Почта не принимает посылки как попало. Есть **бланк:** имя отправителя, адрес, вес, содержимое.

Так и model — это **бланк** по которому данные должны быть оформлены. UUID здесь, поле игры здесь.

---

**mapper — таможня**

Посылка пришла из-за границы на французском языке. Таможенник **переводит** документы на русский чтобы почта поняла содержимое.

Mapper переводит данные из формата web (JSON) в формат domain (Python-объект) и обратно.

---

**module — начальник отделения**

Он не принимает посылки сам. Он не переводит документы сам. Но именно он **организовал работу** — нанял сотрудников, расставил их по местам, соединил всё вместе.

---

### Единая картина:

```
Клиент пришёл с посылкой (запрос от пользователя)
        ↓
[route]   — стойка приёма, определила куда направить
        ↓
[model]   — проверила по бланку правильно ли оформлено
        ↓
[mapper]  — таможня перевела на язык domain
        ↓
        ... domain думает ...
        ↓
[mapper]  — таможня перевела ответ обратно на язык web
        ↓
[route]   — стойка выдала ответ клиенту
        
[module]  — начальник который всех нанял и расставил
```

### Язык domain — это просто Python-объект (класс)

---

**JSON** — это текст, который понимает браузер:
```json
{
    "uuid": "550e8400",
    "field": [[0, 1, 0],
              [2, 0, 1],
              [0, 0, 2]]
}
```

---

**Domain-объект** — это класс Python, который понимает твой код:
```python
class Game:
    uuid: str
    field: Board  # не просто список, а отдельный объект!

class Board:
    cells: list  # [[0,1,0],[2,0,1],[0,0,2]]
```

---

### В чём разница?

| | JSON | Domain-объект |
|---|---|---|
| **Что это** | Текст | Объект в памяти |
| **Кто понимает** | Браузер, сеть | Python-код |
| **Методы** | Нет | Есть |
| **Типы данных** | Только текст/числа/списки | Любые Python-типы |

---

### Главное отличие — у domain-объекта есть методы:

```python
class Board:
    cells: list

    def is_full(self):
        # проверить заполнено ли поле
        ...
    
    def get_cell(self, x, y):
        # получить конкретную клетку
        ...
```

**JSON так не умеет** — он просто тупо хранит данные без какого-либо поведения.

---

### Именно поэтому нужен mapper:

```python
# Пришёл JSON (текст из браузера)
json_data = '{"uuid": "550e8400", "field": [[0,1,0]...]}'

# mapper превращает его в живой объект
game = Game(
    uuid=json_data["uuid"],
    field=Board(cells=json_data["field"])
)

# теперь можно вызывать методы
game.field.is_full()  # JSON так не умеет
```

**Domain-объект** — это JSON которому дали мозги.

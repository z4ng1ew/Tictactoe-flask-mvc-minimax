**DI** = **Dependency Injection** = **Внедрение зависимостей**

---

### Что такое "зависимость"?

Если класс А **не может работать без** класса Б — значит А **зависит** от Б.

В твоём проекте:
```
Сервис зависит от Репозитория
Репозиторий зависит от Хранилища
```

---

### Без DI — плохо:

```python
class Service:
    def __init__(self):
        # Сервис САМ создаёт репозиторий
        self.repo = Repository()  
```

Проблема — сервис жёстко привязан к репозиторию. Захочешь поменять репозиторий — полезешь внутрь сервиса.

---

### С DI — хорошо:

```python
class Service:
    def __init__(self, repo):
        # Репозиторий ПЕРЕДАЮТ снаружи
        self.repo = repo
```

Сервис не знает откуда пришёл репозиторий — ему передали готовый. Это и есть **внедрение** (injection — укол, впрыскивание) зависимости снаружи.

---

### А Container (класс в слое di) — это:

Один файл где **собирается всё приложение:**

```python
class Container:
    storage = Storage()           # создали хранилище
    repo = Repository(storage)    # передали в репозиторий
    service = Service(repo)       # передали в сервис
```

Как **инструкция по сборке** — все детали есть, Container объясняет как их соединить.
